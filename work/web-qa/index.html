01 / CONTEXT

개인 웹사이트를 검증 대상으로

개인 포트폴리오의 기능, 링크, 화면 표시, 기본 접근성 구조와 콘텐츠 일관성을 검토했습니다. 수동 확인과 코드 검토의 범위를 기록하고, 주요 영역을 반복 확인할 수 있는 기본 회귀 테스트를 작성·실행했습니다.

02 / SCOPE

무엇을 확인했는가

수동·정적 검토
주요 콘텐츠와 링크 구성, 반응형 CSS, 테마·메뉴 처리, 제목과 접근성 속성 등을 검토했습니다. 코드 구조 확인과 실제 브라우저 확인은 보고서에서 구분했습니다.
기초 회귀 자동화
내비게이션·본문·주요 제목의 표시, 프로젝트 링크 속성, 연락 링크 표시, 좁은 뷰포트에서 주요 영역 표시를 확인합니다.
실행 구성
Playwright를 사용하고 Chromium·Firefox·WebKit 실행 구성을 두었습니다. 코드에는 390×844 뷰포트 확인이 포함돼 있습니다.

03 / HISTORICAL RECORD

당시 결과와 현재를 구분하기

2026.06.18

12개 테스트 통과 기록

기존 회귀 프로젝트 README의 당시 결과입니다. 이번 v2.1 개편의 시험 결과나 실기기 검증 결과를 뜻하지 않습니다.

기존 QA 보고서의 내용과 현재 화면은 일부 달라졌습니다. 보고서는 당시 검토 기록으로 보존하며, 최근 개편의 검토와 시험은 별도의 기록으로 구분합니다.

04 / RECENT REVIEW

2026.10 · 개인 사이트 개편 검토

현재 직무와 개인 연구의 진행 상태가 정확히 읽히도록 요구사항을 정하고, 화면·문구·사용자 흐름을 직접 검토해 피드백했습니다. 구현과 자동 검사에는 AI의 지원을 사용했습니다.

직접 검토
경력과 개인 연구의 구분, 평가 사례의 맥락, 한국어 문장과 정보 순서를 확인하고 수정 방향을 제시했습니다.
AI 지원
HTML·CSS·JavaScript와 Node.js 기반의 정적 페이지 구현, 반응형·링크·키보드 동작에 대한 회귀 검사와 수정에 AI의 도움을 사용했습니다.
기록 구분
2026년 6월의 시험 기록과 이번 개편의 확인 범위를 구분합니다. 자동 검사 통과를 사용자의 독립 구현 숙련도나 실기기·스크린리더 검증으로 확대하지 않습니다.

05 / LIMITS

자동화가 확인하지 않는 것

  • 링크 속성이 있다는 사실만으로 외부 목적지의 정상 응답을 보장하지 않습니다.
  • 좁은 뷰포트의 영역 표시만으로 모든 모바일 사용성과 실기기 동작을 검증하지 않습니다.
  • 기본 접근성 구조 확인은 전체 접근성 적합성 검증과 다릅니다.

이 사례는 기초적인 테스트 자동화 경험을 보여줍니다. 전체 자동화 체계를 독자적으로 설계·운영한 경력으로 확대하지 않습니다.
