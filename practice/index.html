01 / AI 평가 업무

Voice AI Evaluation

발화가 겹치는 구간을 살펴봅니다

한국어 응답과 오디오/TTS를 평가할 때, 발화 시점과 응답 내용, 음질을 구분해 살펴보고 판단의 근거를 정리합니다.

합성 신호로 구성한 설명용 타임라인입니다. 실제 고객 음성은 사용하지 않았습니다.

입력
사용자 발화와 응답 A·B의 시작 시점
살펴볼 점
사용자의 말이 끝나기 전에 응답이 시작하는지 같은 시간축에서 대조합니다.
관찰 결과
A는 사용자 발화와 겹치고, B는 발화가 끝난 뒤 시작합니다.

1 / 6 · 발화 구간 확인사용자 발화의 시작과 끝을 비교 기준으로 잡습니다.뒤에 놓이는 응답도 같은 시간축에서 살펴봅니다.

1 / 6
전체 작업 과정 읽기

  1. 발화 구간 확인

    사용자 발화의 시작과 끝을 비교 기준으로 잡습니다.

    뒤에 놓이는 응답도 같은 시간축에서 살펴봅니다.

  2. 응답 시점 비교

    응답 A와 B가 시작하는 위치를 나란히 봅니다.

    A는 사용자 발화가 끝나기 전에, B는 끝난 뒤에 시작합니다.

  3. 겹침 구간 표시

    사용자 발화와 응답 A가 겹치는 구간을 표시합니다.

    겹치는 위치를 남겨 다음 검토에서 다시 확인할 수 있게 합니다.

  4. 평가 항목 분리

    대화 타이밍과 기술적 음질을 각각의 항목으로 나눕니다.

    발화가 겹친다는 관찰만으로 음질의 우열까지 판단하지 않습니다.

  5. 관찰 재확인

    사용자 발화의 종료 시점과 두 응답의 시작 시점을 다시 대조합니다.

    비교 기준을 유지한 채 A의 겹침과 B의 시작 위치를 확인합니다.

  6. 판단 정리

    발화 시점의 차이와 추가로 들어야 할 항목을 함께 정리합니다.

    A는 겹침, B는 발화 종료 후 시작으로 기록합니다. 음질은 원본 청취가 필요합니다.

02 / 소프트웨어 QA 업무

Quality Assurance & Evidence

오류를 재현하고 원인을 좁힙니다

예상한 동작과 화면의 차이를 확인하고, 문제가 나타나는 조건을 좁혀 다시 검사할 수 있도록 기록합니다.

합성 작업 데이터로 구성한 필터 검사 예시입니다. 고객사 화면이나 로그는 사용하지 않았습니다.

입력
‘검토 완료만’ 필터를 선택한 작업 목록
살펴볼 점
예상 목록과 표시 목록을 비교하고, 항목을 추가한 뒤에도 필터가 적용되는지 살펴봅니다.
관찰 결과
완료 항목 B만 남아야 하는 조건에서 대기·예외 항목이 함께 표시되는 차이를 확인합니다.

1 / 6 · 문제 확인‘검토 완료만’을 선택한 뒤 화면에 남은 항목을 살펴봅니다.완료 항목 B와 함께 대기 항목 A, 예외 항목 C가 표시됩니다.

1 / 6
전체 작업 과정 읽기

  1. 문제 확인

    ‘검토 완료만’을 선택한 뒤 화면에 남은 항목을 살펴봅니다.

    완료 항목 B와 함께 대기 항목 A, 예외 항목 C가 표시됩니다.

  2. 재현 절차 기록

    필터 선택, 항목 추가, 목록 확인의 순서를 기록합니다.

    각 단계의 입력과 상태를 남겨 같은 조건으로 다시 검사합니다.

  3. 예상과 동작 비교

    예상한 완료 목록과 화면에 표시된 목록을 나란히 봅니다.

    완료 항목 이외의 상태가 남는 것이 관찰한 문제입니다.

  4. 원인 후보 분리

    항목을 추가한 뒤 필터 조건을 다시 적용하는지 살펴봅니다.

    표시 결과와 조건 적용을 나누어 보고, 적용 누락을 원인 후보로 둡니다.

  5. 조건 적용 후 재검사

    완료 상태만 선택하는 조건을 적용한 목록과 비교합니다.

    이 조건에서는 완료 항목 B만 남습니다.

  6. 확인 범위 기록

    재현 순서와 비교 결과, 추가로 검사할 조건을 정리합니다.

    현재 확인한 조건을 기록하고, 다른 필터와 상태 전환은 후속 검사 항목으로 남깁니다.

03 / 독립 프로젝트 · 작업 구조 설계

AI Systems & Orchestration

AI에 맡길 일과 사람이 확인할 일을 나눕니다

작업을 나누는 기준과 결과를 검토하는 절차를 설계합니다. 근거가 부족한 결과는 수정으로 돌리고, 외부 실행은 사람이 확인할 단계로 구분합니다.

문서 작성 요청을 바탕으로 구성한 작업 흐름 설계 예시입니다. 실제 에이전트를 실행하는 화면은 아닙니다.

입력
안내 문서의 초안과 검토표를 만드는 요청
살펴볼 점
초안 작성, 사실 대조, 형식 검토를 나누고 결과를 다시 모아 확인합니다.
관찰 결과
수정 경로와 사람의 검토 단계를 포함한 작업 흐름을 정리합니다.

1 / 7 · 요청 범위 정리필요한 산출물과 허용된 작업 범위를 먼저 정합니다.문서 초안과 검토표가 이번 요청의 산출물입니다.

1 / 7
전체 작업 과정 읽기

  1. 요청 범위 정리

    필요한 산출물과 허용된 작업 범위를 먼저 정합니다.

    문서 초안과 검토표가 이번 요청의 산출물입니다.

  2. 작업 나누기

    초안 작성, 사실 대조, 형식 검토로 작업을 나눕니다.

    각 작업에서 확인할 내용과 제출할 결과를 구분합니다.

  3. 작업 조율

    서로 나누어 진행할 작업과 함께 확인할 기준을 배치합니다.

    작성 결과와 검토 의견이 어느 단계에서 합쳐지는지 표시합니다.

  4. 결과 검토

    근거, 형식, 요청과의 일치 여부를 확인하는 단계로 모읍니다.

    초안을 받는 단계와 검토를 마치는 단계를 구분합니다.

  5. 수정으로 되돌리기

    근거가 부족한 부분은 사유와 함께 작성 단계로 돌려보냅니다.

    수정된 결과도 같은 기준으로 다시 검토하도록 연결합니다.

  6. 사람의 검토

    외부 실행과 게시처럼 확인이 필요한 작업의 경계를 정합니다.

    AI의 결과 정리와 사람의 실행 결정을 별도 단계로 둡니다.

  7. 산출물 정리

    검토한 초안과 남아 있는 확인 사항을 함께 정리합니다.

    수신자가 결과와 후속 확인 항목을 구분해 읽을 수 있게 합니다.

04 / 독립 연구 · 한국어 맥락

Korean Language & Context

문맥을 대조해 의미를 좁혀갑니다

한국어에서 생략된 대상과 장소가 앞선 대화에 따라 어떻게 달라지는지 살펴봅니다. 정보가 부족하면 무엇을 더 확인해야 하는지 남깁니다.

설명을 위해 작성한 일상 대화 예시입니다. 실제 연구 문항이나 모델 응답을 사용하지 않았습니다.

입력
‘그거 거기 두면 돼.’라는 문장과 두 가지 앞선 대화
살펴볼 점
‘그거’와 ‘거기’가 가리키는 대상과 장소를 문맥에 비추어 살펴봅니다.
관찰 결과
자료 파일과 배송 상자처럼, 같은 문장이 문맥에 따라 다른 대상을 가리킬 수 있습니다.

1 / 5 · 문장만 읽기‘그거 거기 두면 돼.’를 앞선 대화 없이 읽습니다.이 문장만으로는 대상과 장소를 정하기 어렵습니다.

1 / 5
전체 작업 과정 읽기

  1. 문장만 읽기

    ‘그거 거기 두면 돼.’를 앞선 대화 없이 읽습니다.

    이 문장만으로는 대상과 장소를 정하기 어렵습니다.

  2. 필요한 정보 찾기

    대상과 장소를 알기 위해 어떤 정보가 필요한지 나눕니다.

    앞서 언급한 물건과 놓을 위치를 확인해야 합니다.

  3. 문맥 A 대조

    자료 파일과 서류함 윗칸을 언급한 대화를 함께 읽습니다.

    ‘그거’는 자료 파일, ‘거기’는 서류함 윗칸을 가리키는 것으로 읽힙니다.

  4. 문맥 B 대조

    배송 상자와 출입문 안쪽을 언급한 대화를 함께 읽습니다.

    같은 문장이 이번에는 배송 상자와 출입문 안쪽을 가리킵니다.

  5. 부족한 정보 확인

    앞선 대화가 없다면 대상과 장소를 다시 확인합니다.

    임의로 뜻을 채우기보다 필요한 정보를 묻는 편이 적절합니다.
